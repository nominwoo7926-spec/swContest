# 개인화·실측·물리 설비 연결 상태

현재 APK는 Quest에서 키·팔 도달 길이를 입력하고, 작업 직후 불편감 1~5점을 기록하고, AI 제안을 읽은 뒤 승인/거절할 수 있다. **승인은 가상 책상·벨트에만 적용한다. 실제 모터·PLC·전동 책상에 명령을 보내지 않는다.** 장비의 모델·통신 프로토콜·안전 회로가 확인되기 전에는 임의 명령을 만들지 않는다.

## 시작 방향과 손이 닿는 범위

앱은 보정 순간의 헤드셋 정면을 공장 작업 정면에 맞춘다. 현실의 벽 반대쪽, 장애물이 없는 공간을 보고 2초간 정지하면 그 방향으로 시작한다. 이미 보정한 뒤에는 빈손으로 `Y`를 1초 누르고 새 방향을 보고 다시 2초간 선다. `Y` 짧게 누르기는 개인화 메뉴다. 첫 집기 지점은 보정 위치에서 수평 약 0.76m로 이동했고 벨트·책상 시작 높이는 0.82m다. 그래도 컨트롤러가 현실 경계에 닿는다면 실제 빈 공간 안에서 룸스케일 경계를 다시 잡아야 한다. 경계를 벽이나 물건 너머로 넓히지 않는다.

## VR에서 입력하고 기록하는 방법

1. 처음 2초 보정을 마치고 작업자 뒤쪽을 본다. 왼손 `Y`를 짧게 눌러 보고서를 연다. 평소 1/3/5kg·−/+ 다섯 버튼은 숨고, 같은 위치에 메뉴용 다섯 버튼만 보인다.
2. 보고서의 `HEIGHT`를 누르면 키 입력이 열린다. cm 단위로 `−10/−1/+1/+10`으로 고치고 `NEXT`. 초기값은 HMD 눈높이에서 계산한 **추정치**다.
3. `ARM REACH`: 한쪽 어깨에서 손끝까지의 대략적인 길이를 cm로 고치고 `NEXT`를 누르면 보고서로 돌아간다. 초기값은 키 비례 추정치다. 직접 측정했다면 그 값을 사용한다.
4. 부품 종류, 속도, 높이를 유지하며 10초 이상 작업한다. 구간이 끝나면 보고서의 `RATE`를 눌러 실제 느낀 불편감 1~5를 누른다. 1은 낮음, 5는 높음이다. 누르는 순간 그 구간의 초당 센서 요약과 점수가 저장된다. 누르지 않으면 미평가 데이터로 분리된다.
5. `REPORT`에서 상대부하, 사용된 정책(`RULE FALLBACK` 또는 검증된 `ML VALIDATED`), 제안값을 읽는다. `APPLY`가 있을 때만 가상 장비 목표가 바뀐다. `SKIP`은 거절한다. `CLOSE`는 평소 작업 버튼으로 복귀다.

저장은 Quest 앱 데이터의 `FactoryML` 폴더에만 한다. `worker_profile_v1.json`에는 익명 ID와 입력한 두 치수를, `manufacturing_trials_v3.csv`에는 평가를 입력한 작업 구간을, `manufacturing_unlabeled_v3.csv`에는 미평가 구간을, `agent_events_v3.csv`에는 제안·승인·거절·가상 실행·5초 후 결과를 담는다. 실명은 수집하지 않지만 자세·체형 정보도 개인정보로 취급해야 하므로 참가자 동의와 삭제 절차를 마련한다.

## 규칙 출력을 정답으로 학습하지 않는 절차

한 참가자가 같은 무게 부품으로 두 구간을 수행한다. 첫 구간에서는 설정을 고정하고 작업한 뒤 불편감 점수를 남긴다. 제안을 승인해 **한 번에 책상 높이 또는 벨트 속도 하나만** 바꾼다. 기기가 목표에 도달한 뒤 같은 길이로 두 번째 구간을 수행하고 다시 점수를 남긴다. 둘의 자세 기반 상대부하, 완료 수/분, 적체, **사용자 점수**를 함께 비교한다. 참가자 간 조건 순서를 바꿔 반복한다. 전후 차이는 관찰 결과이며 순서·학습·피로 영향을 통제하기 전에는 인과 효과로 주장하지 않는다.

PC에 데이터 복사:

```powershell
powershell -ExecutionPolicy Bypass -File Tools/Pull-QuestMLData.ps1
```

전후 쌍 표와 학습·검증:

```powershell
$pythonExe = 'C:\Users\nominwoo\AppData\Local\Programs\Python\Python311\python.exe'
& $pythonExe Tools/Analyze-PairedInterventions.py
& $pythonExe Tools/Train-ErgonomicsModel.py
```

위 경로는 현재 작업 PC에서 확인한 Python 설치 위치다. 다른 PC에서는 해당 PC의 `python.exe` 경로를 쓴다. 학습기는 **실제 입력한 불편감**으로 작업 구간 단위 분류기를 학습한다. 4개 세션·8개 안정 구간·100초 이상과 양쪽 불편감 범주가 없거나, 참가자/세션 보류 검증이 부족하면 `ErgonomicsModel.json`을 만들지 않는다. 개인 프로필이 네 개 이상이면 참가자 전체를 검증용으로 분리한다. 합성 테스트 데이터는 임시 폴더에서만 만들고 모델로 배포하지 않는다. 검증 모델 파일을 만든 뒤 APK를 다시 빌드해야 Quest에서 읽는다. 새 구간이 쌓일 때 다시 학습·검증할 수 있지만, **데이터가 많아진다고 개인별 정확도가 자동 보장되지는 않는다.** 현재 모델은 *불편감 위험 예측*이며 설정 변경의 인과 효과 예측 모델이 아니다.

## 실물 연동 전에 필요한 것

- 벨트 구동기와 전동 책상의 제조사·모델, 실제 제어 방식(PLC/시리얼/USB 등), 명령·응답 문서.
- 실제 속도와 높이를 되읽을 센서 및 단위, 허용 범위, 움직임 속도와 정지 오차.
- 독립적인 물리 비상정지, 끼임 방지, 사람/손이 작업면에 있을 때 동작 금지, 통신 실패 시 안전 상태, 수동 우선권과 현장 감독자 확인.
- 각 명령에 대해 `제안 → 사용자 승인 → 제어기 수락 → 센서 실측 확인 → 실패 시 정지/오류 표시`의 기록.

장비가 확인되면 먼저 모터를 연결하지 않은 모의 제어기에서 위 전체 흐름을 시험한 다음, 안전 회로가 있는 소형 실물 시제품으로 단계적으로 확장한다. `PHYSICAL DEVICE: NOT CONNECTED`를 지우는 것은 실제 수신·실측 검증을 통과한 뒤다.
