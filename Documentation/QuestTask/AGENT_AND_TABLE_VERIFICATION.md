# Quest 작업대와 에이전트 검증

## 사용자가 실제로 느끼는 높이 변화

작업대 상판 중심의 기본 높이는 0.82m이며 0.55~1.20m 범위에서 움직인다. 벨트 작업면도 0.82m로 낮췄다. 첫 집기 지점은 보정 위치에서 수평 약 0.76m다. 벨트 끝과 나란히 놓인 책상 위 집기 위치 3곳은 상판과 함께 움직이고, 나머지 대기 부품 9개는 벨트에 남는다. 헤드셋과 컨트롤러의 현실 위치는 이동하지 않는다. 따라서 책상을 낮추면 사용자는 손을 실제로 더 낮은 위치까지 내려야 부품을 잡을 수 있다. 낮은 자세로 잡을 때의 아래쪽 팔 뻗기 부담도 추정 점수에 반영한다.

Quest 컨트롤러가 물리적인 저항을 만들지는 못한다. 서 있는 채 팔을 충분히 내리거나 상체를 숙여 닿을 수 있으며, 무릎을 굽히도록 강제하지 않는다. 허리 부담은 머리의 하강과 전방 이동으로 추정할 뿐 실제 허리·무릎 관절을 측정하지 않는다. 0.55m는 실제 바닥 높이가 아니다.

작업대가 움직이는 동안 상판 주변에 손이 있거나 부품을 들고 있으면 이동이 일시정지된다. 손을 빼고 부품을 내려놓으면 목표 높이까지 천천히 계속 이동한다.

## VR 조작

고정 조작판은 작업자 뒤쪽에 있으며 제3자 카메라에는 나오지 않는다. 몸을 돌려 조작판에 컨트롤러를 직접 가져다 댄다. 버튼을 누를 때 Grip이나 A/B는 필요하지 않다. 한 번 작동한 뒤 손을 떼고 다시 대야 다음 단계가 입력된다.

| 표시 | 기능 |
| --- | --- |
| 왼쪽 `1/3/5` | 앞으로 나올 부품의 kg를 고정 선택. 선택 버튼은 눌린 채 유지 |
| 오른쪽 `−/+` | 벨트 속도를 0.10m/s씩 조절. 아래에 현재 m/s 표시 |

시작 시 1kg가 선택되고 에이전트 관찰이 켜진다. 수동 속도 조절 후 20초간 에이전트는 벨트 속도에 개입하지 않는다. 에이전트의 새 높이·속도 제안은 바로 적용되지 않고 뒤쪽 보고서 화면의 `APPLY`를 눌러야 가상 설비에 적용된다. `SKIP`은 제안을 버린다. 기존 작업 버튼 5개는 유지하고 별도 메뉴가 열릴 때만 설정/피드백 버튼 5개로 전환한다.

왼손 `Y`를 **짧게 눌렀다 놓으면** 뒤쪽 보고서 메뉴가 바로 열린다. `Y`를 약 1초 길게 누르면 기존처럼 빈손 재보정된다. 보고서의 `HEIGHT`에서 키와 팔 도달 길이를 cm 단위로 입력하며, 처음 표시값은 머리 높이에서 추정한 값이라 정확한 신체 치수라고 주장하지 않는다. 작업을 10초 이상 수행한 후 보고서의 `RATE`에서 1~5 버튼을 눌러 해당 구간의 불편감을 저장한다. 보고서의 제안을 승인/거절하고 메뉴를 닫으면 원래 1/3/5kg와 −/+ 버튼으로 돌아간다.

## 에이전트의 실제 흐름

1. 목표: 상대 부하를 낮추면서 부품 적체와 처리량을 관리한다.
2. 관찰: 머리·손 추적, 마지막으로 집은 손 높이, 부품 무게, 7개 부하 추정치, 대기열, 벨트 속도, 사용자 불편함 점수.
3. 판단: 보정된 어깨 높이에서 초기 책상 높이를 정하고, 실제 집을 때 손과 머리 높이로 보정한다. 높은 부하 또는 적체가 일정 시간 이어지면 벨트 속도를 조절한다.
4. 승인 후 도구 실행: 컨베이어 속도와 **가상** 작업대 목표 높이를 변경한다. 실물 장비 제어는 아직 연결하지 않았다.
5. 기억과 피드백: 입력한 신체 치수·지난 집기 높이·1~5점 불편감을 로컬에 기록한다. 조절 전후의 수치와 센서 오류를 `agent_events_v3.csv`에 남긴다.
6. 결과 확인: 조절마다 별도의 ID를 부여하고 5초 뒤 부하·대기열·완료 수를 `OUTCOME` 이벤트로 기록한다. 그 사이 추적이 끊기면 성공으로 간주하지 않고 `OUTCOME_INVALID`를 기록한다.

현재 정책은 설명 가능한 규칙 기반이다. 학습 모델 파일이 없으면 안전 규칙으로 계속 동작한다. 학습 모델이 있더라도 현재 모델은 관찰한 순간의 불편 위험을 예측한다. 특정 높이로 바꾸었을 때 생길 효과를 검증된 인과 모델로 예측하는 단계는 아직 아니다. `최적 높이`라는 표현은 실험 검증 전에는 사용하지 않는다.

## 데이터와 검증

- 별도 VR 메뉴에서 실제 사용자가 입력한 1~5점 불편감을 해당 작업 구간의 센서 기록과 묶어 `manufacturing_trials_v3.csv`에 저장한다. 점수를 누르지 않으면 정답 라벨이 없다.
- 앱을 중단하거나 1시간 이상 평가를 입력하지 않으면 미평가 기록을 `manufacturing_unlabeled_v3.csv`로 따로 보관한다. 이 기록은 바로 학습에 쓰지 않는다.
- `agent_events_v3.csv`는 제안, 승인/거절, 가상 조절, 5초 후 관찰, 불편감 입력, 센서 중단을 별도로 기록한다.
- 저장 경로: Quest 앱 데이터의 `FactoryML` 폴더. PC로 가져오기: `Tools/Pull-QuestMLData.ps1`.
- 학습 입력에는 가상 책상 높이, 속도, 익명 프로필과 키·팔 길이가 포함된다. 학습·검증은 여러 프로필이 있으면 참가자 단위, 한 명뿐이면 세션 단위로 분리한다.
- 학습 스크립트는 최소 4개 세션, 8개 안정 작업 구간, 100초의 라벨 데이터와 학습/검증 양쪽의 불편함 범주를 요구한다. 보류 성능이 미달하면 모델을 생성하지 않는다. 모델이 없어도 규칙 기반 제안은 동작한다.
- 표시는 의료 진단이 아닌 VR 동작 기반 상대 부하 지표다. 부품의 1/3/5kg은 시뮬레이션 값이며 컨트롤러에 실제 무게가 가해지지는 않는다.

## 대표 테스트 케이스

| 사례 | 입력 | 예상 결과 | 확인할 실제 결과 |
| --- | --- | --- | --- |
| 정상 집기 | 책상 0.82m, 양손 Grip, 앞 부품에 손 닿음 | 가장 가까운 손이 한 부품만 집음 | 완료 수·무게·부하 |
| 최저 높이 | 책상 0.55m, 손은 이전 0.82m 높이에 유지 | 박스가 내려가고 집히지 않음 | 실제 박스 높이와 집기 여부 |
| 추적 손실 | 헤드셋 추적/포커스 사라짐 | 에이전트가 조절을 멈추고 `SENSOR WAIT` 기록 | 장치 설정 변화 여부 |
| 적체 포화 | 12칸이 모두 참 | 새 부품 공급만 대기, 벨트 시각 효과 지속 | 공급 수와 대기열 |
| 5kg 선택 | 작업자 뒤쪽 `5` 터치 | 새로 공급되는 부품만 5kg | 선택 상태와 신규 부품 표시 |
| 수동 속도 조절 | `+` 터치 | 0.10m/s 증가, 20초간 자동 속도 개입 보류 | 현재 속도 표시 |
| 모델 없음 | JSON 학습 파일 없음 | 안전 규칙으로 계속 동작 | 상태와 앱 오류 없음 |

Unity Play 모드 자동 검증에서 정상 집기, 최저 높이의 박스 하강과 옛 높이 집기 실패, 제안 후 승인 전 미작동·승인 후 가상 높이 변경, 추적 손실 시 개입 중단, 12칸 포화, 5개 버튼 전환, 동작 기록 재생을 통과했다. 이 변경의 새 APK와 Quest 착용 테스트는 별도로 확인해야 한다.

## 현장에서 필요한 최소 실험

서로 다른 참가자 최소 5명이 각자 여러 구간을 수행하고 VR 메뉴에서 각 구간 직후 불편함 1~5점을 입력해야 한다. 참가자 동의, 익명 프로필 분리, 장비 조건 순서 교차가 필요하다. 비교 지표는 평균·최대 상대부하, 부하 65 이상 시간, 완료 부품 수, 최대 적체량, 작업 시간, 실제 불편감이다. `Analyze-PairedInterventions.py`는 한 설정만 바뀐 연속 작업 구간의 전후 차이를 기록하지만 무작위 순서와 반복 실험 없이는 인과적 효과로 주장하지 않는다.
