# 경남 AI·SW 경진대회 제출·검증 체크리스트

## 정확한 한 문장

Quest 2의 머리·양손 위치, 입력한 체형, 가상 공정과 사용자 불편감 평가를 관찰하고, 작업대 높이·벨트 속도를 제안해 **사용자 승인 후 가상 설비만** 조절하고 결과를 기록하는 VR 제조 작업자 보조 에이전트 시제품이다.

실제 무게·근육 부하·산업 설비를 측정하거나 제어하지 않는다. 현재 기본 정책은 설명 가능한 규칙 기반이다. 검증된 학습 모델이 설치된 경우에만 그 모델의 불편 위험 예측을 추가 사용한다.

## 먼저 끝낼 End-to-End

1. Quest 라이브러리에서 `Adaptive Workbench VR`을 연다. 구형 `NOVA` 앱과 혼동하지 않는다.
2. 컨트롤러 두 개를 추적시키고 보정을 완료한다.
3. 작업자 뒤쪽 조작판의 `1/3/5`에 컨트롤러 끝을 대어 공급 무게를 바꾼다. 선택 버튼은 계속 눌린 상태로 보인다.
4. 양손 Grip을 누른 상태에서 부품 하나를 잡고, 오른쪽 완료 상자 안에서 놓는다.
5. `Y` 짧게 누르기로 메뉴를 열어 키·팔 길이를 입력하고, 안정 작업 구간 후 불편감 1~5를 실제로 입력한다.
6. 반복 작업·높은 상대 부하 또는 적체 후 `REPORT`의 제안 이유와 목표 높이/속도를 확인하고 `APPLY`를 눌러 **가상 설비만** 조절한다.
7. 5초 후 `agent_events_v3.csv`의 `ACTION`과 동일 ID의 `OUTCOME`을 확인한다. 추적이 끊겼다면 `OUTCOME_INVALID`라고 표시하고 성공으로 세지 않는다. `manufacturing_trials_v3.csv`에 사용자 점수와 센서 기록이 한 구간으로 저장됐는지도 확인한다.

위 흐름이 헤드셋에서 실제로 동작하는 짧은 영상이 확보되기 전에는 신규 기능 추가보다 오류 수정에 집중한다.

## 실기기 테스트 표

| 입력 | 기대 결과 | 제출 전에 기록할 실제 결과 |
| --- | --- | --- |
| 1kg 버튼 접촉 후 공급 | 1kg만 새로 공급 | Quest 영상 시각·부품 표시 |
| 3kg 또는 5kg 버튼 접촉 후 공급 | 새 부품에 해당 무게만 표시 | 최소 3개 공급 중 관찰값 |
| 한손 Grip만 누른 채 부품 접촉 | 새 부품이 집히지 않음 | 영상 시각 |
| 양손 Grip + 근접 부품 | 한 개만 집힘 | 영상 시각 |
| 파란 `−`/초록 `+` 버튼 접촉 | 벨트 속도 단계 변화 | 상태판 전후 값 |
| 높은 부하/적체 → 제안 → 승인 | 승인 전 변화 없음, 승인 후 가상 목표 변화 | `PROPOSAL`·`APPROVED`·`ACTION`·`OUTCOME`과 장면 |
| 메뉴에서 불편감 1~5 입력 | 해당 작업 구간의 센서값과 점수 함께 저장 | Quest 화면과 CSV 한 구간 |
| 추적 손실 | 자동 개입 중지, `SENSOR WAIT` | 영상/이벤트 로그 |
| 12칸 적체 | 공급만 대기, 앱/풀 안정 | 대기열·프레임 안정성 |

Unity 자동 테스트는 입력 시뮬레이션으로 위 논리 일부를 검증하지만 Quest 착용 테스트의 대체물이 아니다.

## 실제 효과를 주장하려면

참가자 동의 후 익명 프로필을 부여한다. VR 메뉴의 1~5점은 해당 작업 구간의 센서 기록과 연결된다. 한 설정만 바꾼 연속 전후 구간을 같은 참가자·부품 무게로 반복하고 조건 순서를 교차해야 효과를 평가할 수 있다. 평가 입력이 없는 구간은 학습 정답으로 쓰지 않는다. 이름·연락처·영상 얼굴을 학습 CSV에 넣지 않는다. 현재 실제 참가자 라벨 데이터는 없으므로 예측 정확도와 개선 효과를 아직 주장할 수 없다.

PC 복사: `powershell -ExecutionPolicy Bypass -File Tools/Pull-QuestMLData.ps1`  
실측 요약: `Tools/Analyze-QuestExperiment.py`  
전후 쌍 점검: `Tools/Analyze-PairedInterventions.py`  
학습 모델(충분한 실제 데이터가 있을 때만): `Tools/Train-ErgonomicsModel.py`

보고서는 완료 부품/분, 평균 최고 상대부하, 상대부하 65 이상 시간 비율, 최대 적체, 불편함 점수를 표시한다. 앱의 부하 점수는 자세 기반 **대리지표**이므로 통증 감소·산업재해 예방을 입증했다고 말하지 않는다. 학습 모델의 불편함 예측 정확도와 자동 개입의 효과는 별개다.

## 영상 구성 제안 (실제 촬영만 사용)

1. 0~15초: 작업자 문제와 평가 지표를 한 문장으로 설명. 시뮬레이션 한계를 작게 명시.
2. 15~40초: Quest 1인칭 녹화에서 부품 선택, 양손 집기, 완료를 연속으로 보여준다.
3. 40~70초: 부하/적체 관찰 → 상태판의 판단 이유 → 가상 책상·벨트의 물리적 위치/속도 변화.
4. 70~90초: `ACTION`→`OUTCOME` 로그와 수동 우선권·추적 손실 안전 대응.
5. 90~120초: 실제 데이터가 있다면 자동/수동 비교 수치와 한계. 없다면 검증 계획이라고 명시.
6. 필요하면 별도의 3인칭 리플레이를 삽입하되, 실제 Quest 동작 장면인 것처럼 표시하지 않는다.

Meta Quest의 첫 화면 녹화는 홈 메뉴 카메라 아이콘으로 시작/종료한다. USB 파일 접근 허용 후 `Oculus/Videoshots`에서 MP4를 복사한다. 녹화 원본, 앱 버전, CSV 원본과 분석 명령을 보존한다.

## 제출 전 주장 점검

- `AI가 최적 높이를 계산했다` → 실제 개입 비교 전에는 `작업자 동작과 규칙에 따라 목표 높이를 계산했다`.
- `실제 근육 부하를 측정했다` → `Quest 추적 정보로 상대 부하를 추정했다`.
- `머신러닝으로 개선을 입증했다` → 실제 참가자 데이터·분리 검증·개입 비교가 있을 때만 사용.
- `물리적 공장을 제어한다` → `가상 설비를 제어하고 실제 적용 가능성을 검토한다`.

## 남은 외부 입력

- 사용자가 직접 Quest를 착용해 최신 앱의 조작 영상 또는 실패 화면을 제공해야 한다.
- 실제 참가자 동의와 작업 구간·불편함 입력이 있어야 효과 비교 및 학습을 할 수 있다.
- 수상 여부는 심사위원과 경쟁작에 달려 있으므로 보장할 수 없다.
