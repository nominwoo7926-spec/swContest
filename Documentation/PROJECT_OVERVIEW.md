# Adaptive Workbench VR — 프로젝트 전체 설명

> 이 문서는 이전 자동조절 시연의 설계 기록이다. 최신 APK의 개인화 메뉴, 불편감 입력, **승인 후 가상 조절**, v3 데이터 형식, 실물 미연결 상태는 [최신 조작 안내](QuestTask/README.md)와 [개인화·실물 연동 상태](QuestTask/PERSONALIZATION_AND_PHYSICAL_ROADMAP.md)를 우선 참조한다.

## 1. 한 문장 정의

Meta Quest 2에서 작업자의 머리·양손 동작, 부품 무게, 작업 지속시간과 반복을 관찰하고, 신체 부하와 공정 적체를 설명 가능한 방식으로 판단하여 가상 작업대 높이와 컨베이어 속도를 조절하는 VR 제조 피지컬 AI 프로토타입이다.

## 2. 해결하려는 문제

고정된 생산속도와 작업대는 모든 작업자에게 동일하게 적합하지 않다. 작은 작업자에게는 먼 도달거리, 큰 작업자에게는 허리 굽힘, 빠른 라인에는 반복·지속 부하가 증가할 수 있다. 이 프로젝트는 작업자를 라인에 맞추는 대신 라인이 작업자의 상태에 적응하는 개념을 검증한다.

## 3. 현재 구현된 사용자 경험

1. Quest 2에서 앱을 실행하고 정면을 본 채 2초 동안 안정 자세로 보정한다.
2. 완료 상자의 `COMPLETE` 아래에서 1·3·5 kg 공급 무게를 VR 버튼으로 선택한다. 기본은 1kg이다.
3. 양손 Grip을 동시에 눌러 가까운 손으로 첫 부품을 집는다.
4. 오른쪽 완료 상자에 부품 전체를 넣고 Grip을 놓는다.
5. 시스템은 7개 부위의 상대부하, 처리량, 적체와 벨트 속도를 갱신한다.
6. 에이전트가 보정된 어깨 높이와 실제 집은 손 높이로 작업대 목표 높이를 정한다. 상판과 집기 위치가 함께 이동한다.
7. 고부하가 지속되거나 대기열이 과도하면 에이전트가 이유를 표시하고 벨트를 감속한다.
8. 안전 상태가 유지되면 정상 속도로 점진 복귀한다. 수동 속도 조절은 20초 동안 우선된다.
9. 불편감 1~5 입력은 현재 작업 화면에서 제거되어 새 센서 기록에는 지도학습용 정답 라벨이 없다.

## 4. VR 조작

- 양손 Grip 동시 입력: 집기 시작. 부품에 더 가까운 손이 소유한다.
- 잡은 손의 Grip 해제: 부품 놓기.
- 왼손 Y 1초: 빈손일 때 사용자 재보정.
- 오른손 B 1초: `.fvr` 동작 기록 중지/재시작.
- 파란 `-`, 초록 `+`: 수동 벨트 속도 조절.
- 1·3·5 kg 버튼: 이후 공급할 부품 종류 선택. 선택한 버튼이 눌린 채 유지된다.
- 완료 표시 아래의 다섯 가상 버튼은 컨트롤러를 가까이 가져다 대면 작동한다. 책상·에이전트는 자동 상태다.

## 5. 공정 시뮬레이션

- 컨베이어 기본속도 0.38 m/s, 조절범위 0.15~0.75 m/s.
- 느린 벨트는 파랑, 보통은 초록, 빠르면 주황·빨강으로 표시한다.
- 최대 12개 FIFO 누적 슬롯과 16개 재사용 부품 풀을 사용한다.
- 부품은 1·3·5 kg의 분석용 무게를 갖지만 실제 힘 피드백은 없다.
- 부품 표면에 무게를 표시하고 운반·대기·낙하 상태에 고체 Collider를 유지한다.
- 풀과 누적 슬롯이 모두 차면 새 공급만 대기하고 벨트 시각 동작은 계속된다.
- 공급은 선택된 1·3·5kg로 반복되며 동시 부품 수만 제한된다. 랜덤 선택 버튼은 없다.
- 작업대 높이는 0.55~1.20m. 상판과 앞쪽 집기 부품이 함께 움직여 손을 실제 다른 높이로 가져가야 한다.

## 6. 부하 추정

왼쪽/오른쪽 어깨·팔·손목과 상체, 총 7개 상대점수를 계산한다. 입력은 도달거리, 위·아래 손 높이, 부품 무게, 잡은 시간, 손 이동거리, 최근 60초 반복 횟수, 머리 하강·전진량이다. 상승은 빠르게, 해제 후 감소는 느리게 평활화한다.

이 점수는 의료 진단, 근전도, RULA/REBA의 대체값이 아니다. VR 센서로 계산한 작업환경 조정용 상대 위험신호이다.

## 7. 적응형 에이전트

현재 기본 정책은 설명 가능한 안전 규칙이다.

- 최고 부하가 약 5초간 위험범위에 유지되면 0.1 m/s 감속.
- 적체가 10개 이상이면 0.1 m/s 감속.
- 낮은 부하와 낮은 적체가 약 10초 유지되면 0.05 m/s씩 기본속도까지 복구.
- 수동 조절 후 20초 동안 자동 개입 보류.
- 작업자 신장과 실제 집기 손 높이로 가상 작업대 목표 높이를 정하고 천천히 이동한다. 손이 상판에 가깝거나 부품을 들면 이동을 일시정지한다.
- 불편함 4~5점을 받으면 자동 모드에서 추가 감속하고 안전해도 바로 복구하지 않는다.
- 추적이 끊기면 자동 개입을 멈추고 `SENSOR WAIT`를 표시한다.
- `MONITORING`, `LOAD WATCH`, `LOAD HIGH - SLOW`, `QUEUE HIGH - SLOW`, `TABLE RAISE/LOWER`, `MANUAL OVERRIDE`로 판단 이유를 공개한다.

## 8. 데이터 수집과 머신러닝

`ManufacturingDataCollector`는 보정 후 1 Hz로 다음 값을 메모리에 수집한다.

- 머리 하강·전진량
- 좌우 도달거리와 손 속도
- 잡은 무게
- 벨트 속도, 작업대 실제·목표 높이, 마지막 집기 손·머리 높이, 적체 수
- 공급 모드
- 7개 부하와 평균
- 완료 개수
- 에이전트 모드와 판단 이유

현재 APK에는 불편감 1~5 입력 화면이 없으므로 새 기록은 `manufacturing_unlabeled_v2.csv`에 분리 저장된다. 조절 요청과 5초 뒤 결과는 `agent_events.csv`에 별도 기록한다. 개인 식별정보는 저장하지 않는다. 실제 참가자의 평가를 작업 구간과 연결하는 절차를 구현하기 전에는 지도학습 데이터 쌍이 아니다.

PC 복사:

```powershell
powershell -ExecutionPolicy Bypass -File Tools/Pull-QuestMLData.ps1
```

학습:

```powershell
python Tools/Train-ErgonomicsModel.py
```

학습기는 외부 패키지 없이 로지스틱 위험모델을 생성하며, 서로 다른 **앱 세션**으로 학습/검증을 분리한다. 최소 100개의 실제 라벨 표본, 4개 세션, 학습·검증 양쪽에 안전(1~3)·고불편(4~5) 사례가 필요하다. 현재 APK만으로는 라벨을 만들 수 없으므로 학습 단계는 보류 상태다. 보류 세션 성능이 기준에 미달하면 모델을 배포하지 않는다. 현재 기본 에이전트는 안전 규칙으로 동작한다.

## 9. 기록과 제3자 시점

- Quest 자체 녹화: 1인칭 영상.
- `.fvr`: 30 Hz 머리·손·부품·부하·완료 상태 동작 데이터.
- `Tools/Pull-QuestSessions.ps1`: Quest의 기록을 PC로 복사.
- Unity `Replay Session File (No Headset)`: 아바타와 제3자 카메라로 재생.
- `Factory Spectator` 창을 OBS로 캡처하면 제3자 발표 영상을 만들 수 있다.

## 10. 주요 코드

- `XRTrackingProvider`: Quest 머리·컨트롤러 포즈와 버튼 입력.
- `UserCalibration`: 바닥·정면·신체 비율 보정.
- `XRGrabTaskTracker`: 양손 Grip 집기, 놓기, 완료 판정.
- `PickupQueue`, `PartSpawner`, `ConveyorPart`: 공급·누적·충돌·재사용.
- `ConveyorController`: 속도와 벨트 색상.
- `AdjustableWorktable`: 실제 가상 상판 이동. 현재 UI에는 수동 높이 버튼이 없다.
- `BodyLoadEstimator`, `BodyLoadVisualizer`: 상대부하 계산과 표시.
- `AdaptiveErgonomicsAgent`: 설명 가능한 폐쇄 루프 제어.
- `ManufacturingDataCollector`: 센서·에이전트 기록. 현재 UI에는 라벨 입력 버튼이 없다.
- `ErgonomicsRiskModel`: JSON 모델 로드 및 실시간 추론.
- `VRSessionRecorder`: 동작 기록과 재생.
- `FullBodyAvatarIK`, `AvatarLoadHeatmap`: 제3자 아바타와 부위별 표면 색상.

## 11. 검증된 것

- C# 런타임·에디터 컴파일.
- Unity 장면 연결 및 단일 작업 루트 검증.
- Android ARM64 IL2CPP APK 빌드.
- Quest 2 설치와 실행.
- 최신 APK는 Quest에 덮어 설치되었다. 컨트롤러 필요 확인 창 때문에 최신 버전의 헤드셋 내 실행 상태는 사용자 확인이 필요하다.
- Quest 위치 추적 문제 수정 후 실제 이동 확인.
- Grip, 기록, 카메라 분리와 주요 계산의 자동 검증 코드 보유.
- Play 검증에서 0.55m 작업대의 부품 하강, 옛 높이에서 집기 실패, 자동 목표 높이 계산, 센서 손실 보류 확인.

## 12. 아직 검증이 필요한 것

- 최신 APK에서 모든 버튼 글자 방향과 가독성.
- 부품 무게 글자 크기와 양안 시인성.
- 자동 감속·복구의 실제 발동 시간.
- Collider 활성화 후 부품 떨림·관통 여부.
- 장시간 수행 시 Quest 2 프레임률과 발열.
- 키와 팔 길이가 다른 사용자 접근성.
- 주관적 피드백과 센서값의 상관관계.
- 학습 모델의 사용자 분리 검증 정확도와 재현율.

## 13. 알려진 한계

- 손가락 핸드 트래킹이 아니라 Quest 컨트롤러 기반이다.
- 스틱 이동·텔레포트가 없고 실제 룸스케일 이동을 사용한다.
- 실제 힘·무게 저항, 현실 모터식 책상, 비상정지 하드웨어는 없다. 실제 허리·무릎 관절도 추적하지 않는다.
- 누적은 안정적인 정렬 버퍼이며 완전 자유 물리 적재는 아니다.
- 실제 사용자 라벨 데이터와 학습 모델은 아직 없다.
- 규칙 기반 정책을 머신러닝이라고 과장해서는 안 된다.

## 14. 남은 로드맵

### 대회 전 필수

1. 서로 다른 사용자 최소 5명, 각 6개 이상 작업 구간 수집.
2. 1·3·5 kg과 느림·보통·빠름 조건을 균형 있게 수행.
3. 고정속도와 자동조절의 평균/최고 부하, 고부하 시간, 처리량 비교.
4. 모델 정확도뿐 아니라 고위험 재현율과 사용자 분리 결과 보고.
5. 2분 내 실패 없는 시연 시나리오와 백업 영상 준비.

### 후속 개발

- 현실 전동 책상 또는 PLC 연동과 사용자 승인 UI.
- 컨트롤러 진동·소리 피드백.
- 세션 요약 리포트와 그래프.
- 적체 센서, 경광등, 비상정지.
- ONNX/XGBoost 등 더 강한 모델과 설명 변수 중요도.
- 핸드 트래킹 또는 실제 PLC/로봇 연동.

## 15. 발표 핵심 메시지

“작업자를 생산라인에 맞추는 대신, 생산라인이 작업자의 부하에 맞춰 스스로 적응한다.”

시연은 5 kg 반복작업 → 부하 상승 → 위험 관찰 → 자동 감속과 벨트 색 변화 → 안정 후 복구 → 결과 로그 확인 순으로 구성한다. 불편감 피드백 및 학습 정확도는 실제 라벨 수집 전까지 시연 성과로 주장하지 않는다.
